## [Unreleased]

### Added
- **The designer and librarian specs now teach their harvest verb (#3477)** — both roles could already RUN it (`restrictedRoleCommands` grants the bare `"bsc ui"` / `"bsc graph"` prefixes, which expand to `Bash(… *)` and already match `… harvest`), and #3475 bounded it to the session's own root — but neither spec mentioned it, and **a capability an agent cannot discover is not a capability**. The **designer** gains a full *Fill the library from real code* section: the verb, that it is READ-ONLY (promoting is a separate deliberate write), that it may only harvest inside its own root, and — the part an agent gets wrong unprompted — that **`buildable: false` is not "reject"**. The most common reason is an unresolved `@/…` import naming *another harvested component*, which is the harvest under-reporting rather than a defect, and those are often the BEST candidates because they are the composed ones; a `@/…` into app state or a feature's logic genuinely is a reject. It also states that the store will NOT catch a bad promotion (#3470 — an unbuildable `srcText` is accepted silently), that candidates land in the `harvested` kit and never straight into a curated one, and that promoting into a real kit is a decision to RAISE rather than take. The **librarian** already documented `harvest`/`curate`, so it gains only the confinement bound. The two pillars stay separate — each spec teaches its own verb in its own terms.
- **⚠️ The designer spec now warns that `bsc ui doctor --fix` over-reaches** — the spec previously instructed passing `--yes` outright, but that prune rule condemns every **page** (a page is a root BY DEFINITION — nothing composes it) and the packaged demo components (isolated on purpose). Against the live store it proposes pruning ten such nodes, all false positives. Until the rule is fixed (#3087) the spec directs reading the dry run and pruning by hand, and notes that deleting the pages tier is not recoverable from inside the session.
- **`bsc ui harvest <repo-dir>` — scan a repo and surface reusable COMPONENT candidates (#3471, epic #3087)** — algorithms could already be harvested mechanically (`bsc graph harvest`, tree-sitter, deterministic), but components had **no equivalent**: the curator was told to "read the landed diff and add it with `bsc ui set`", by hand, one component at a time. So a project that got built never filled the component graph. This is the missing half — parse the repo's real `.tsx`/`.ts` with tree-sitter and lift each React component into a candidate record. A component is a PascalCase-named function that renders JSX (React cannot treat a lowercase name as a component, so the capital is a real signal, not a style rule). Read-only: it emits candidates and stores nothing, exactly like its algorithms sibling, so promoting one stays the curation gate's job and the verb needs no write-scope. **It is deliberately NOT a copy of the algorithms extractor.** That one lifts a function's node text verbatim, which is fine for a self-contained algorithm and *wrong* for a component: a component's module has imports, type declarations and sibling helpers, and its stored `srcText` must be a module the preview can actually COMPILE. So this computes a **closure** — the component, plus the same-file declarations it transitively references, plus exactly the imports those need — pulling in only what is referenced (an unrelated sibling declaration stays behind) while leaving nothing it needs out. It also keeps the wrapping `export`, which tree-sitter parks in a *parent* node, so an arrow component doesn't silently store as a module that exports nothing. `composes` lists component **NAMES**, not ids, because the component graph composes by name — deliberately unlike the algorithms form. **Every candidate carries an honest `buildable` with reasons**, because the store will not tell you otherwise: a `srcText` that keeps unresolved `@/…` imports is accepted today with *zero* complaint (#3470 — `looks_buildable_module` returns false, which makes the syntax gate SKIP entirely), surfacing much later as an unbuildable component far from the write that caused it. **Running it against this repo's own `src/shared/ui` caught a bug no fixture would:** it condemned 13 perfectly good components as "a sketch, not code" because the elision check was a plain substring test for `…` — and `…` is ordinary UI copy (`placeholder = "Select…"`) and ordinary prose in a doc comment. The scanner now skips string literals and comments, so `…` only counts as an elision when it stands in for real code; buildable went 35 → 42 of 93 and the only remaining reason is the legitimate one. Unreviewed candidates default to a `harvested` kit rather than `react-ui`, so a harvest can never contaminate a curated kit. `--worthy-only` keeps what the classifier scores net-positive; glue/provider names and trivial bodies score down. 14 Rust tests over the closure, the composes-by-name rule, the buildability verdicts, id/role conventions, walk order-stability, and the CLI surface.
- **`bsc metrics <project>` — the fleet-wide generation scoreboard (#3449, epic #3260)** — the north-star metric is now *generate any app in under 1s for under $0.01*, and you cannot chase a metric you cannot read. The per-pane token cost was already priced (`crates/logs/src/cost.rs`) but nothing rolled it up to the unit that matters — a whole app's generation. `bsc metrics` does: it sums every fleet pane's $/tokens by the project-scoped pane-id grammar (`<projKey>:<stream>` / `:director` / `:triage`, matched on the `:` delimiter so `foo` never captures `foo-bar`), derives **cache-hit-rate** (`cache_read / (input + cache_read)` — the dial the prompt-caching lever moves), brackets a **wall-clock**, and reads **completion** (issues done/total) from the hub's `plan.db` so an in-flight build's numbers are never mistaken for final. Terse by default (an agent reads it to steer against the target), `--json` for a loop, `--pretty` for a human. **Running it against real data caught a bug no fixture would:** `activity.log` accumulates across every relaunch, so a naive first→last wall-clock read 7730 minutes — the project's whole life, not one generation. The fix splits activity into runs on a 20-minute silence gap and reports the most recent run's span (STEM then read a sane 9m24s). Two honest limitations are documented rather than papered over: the wall-clock is a heuristic until a real generation start/complete event exists (a follow-up), and the $ is only as populated as `tokens.log` — a historical build whose fleet panes were never token-logged reports $0 because there is no data to price. Pure rollup core + thin IO, 15 Rust tests over the attribution, the cache-hit math, the run-splitting, and the terse formatting.
- **`bsc debug` — inspect the RUNNING app's live DOM + preview state (#3437, epic #3260)** — `bsc shot` reads the app's pixels and `bsc navigate` steers it; nothing could **interrogate** it, so a structural UI defect could only be chased by reading source and guessing. Diagnosing "click-drag stopped working in the Design Studio preview" burned a whole session on exactly that: the pan engine was verified healthy in real Chromium (7/7 interaction tests, pan delta measured at every zoom the app uses, then again with the app's exact scaled page geometry), the preview error log was empty, the app was confirmed running current code — and the bug still could not be located, because **nothing could answer "what is actually under that pixel, and what is covering it?"** for the live WebView. The fallback was hand-editing a component to paint a temporary diagnostic badge and reading it back through `bsc shot`. Three verbs replace that: **`hit <x> <y>`** (the topmost element plus its ancestor chain, each with the styles that decide event delivery — `pointer-events`, `z-index`, `opacity`, `transform`, `cursor`, `user-select`), **`probe <selector>`** (the same per match, plus whether the element is the topmost hit at its own centre — *would a click aimed at its middle actually land on it*), and **`frames`** (every mounted preview: the host-side geometry, whether the pan/zoom engine was REQUESTED, whether it actually reached the srcdoc, and the engine's own report). It rides the EXISTING `bsc_appchan` watcher routed by a new `KIND` — no second channel, no second watcher — with the same park-and-ack round-trip `navigate` established, and a test pins that no two verbs' kinds collide. **Read-only by construction:** there is no `eval` verb and a test fails if one is added, because the `designer` role's entire writable surface is `bsc ui` (#2471) and an arbitrary-JS verb on the same binary would be a way around that gate. **Seeing into the preview without weakening the sandbox:** a preview runs at an opaque origin (`sandbox="allow-scripts"`, no `allow-same-origin`), so the host cannot read it — instead the engine is ASKED to describe itself over the `postMessage` channel it already listens on, and a preview that never answers is reported as SILENT, which is itself the diagnosis ("the script is in the srcdoc and is not running" is a different bug from "no engine was ever requested", and the output distinguishes all three). The decisions are pure and unit-tested with every environment capability injected — hit-testing and real rects are precisely what jsdom cannot produce, so leaving them un-injected would have left the logic pinned by nothing.
- **`bsc cad` keeps sharp edges — dual contouring (#3388, kernel #2621)** — the polygonizer ROUNDED every sharp feature, because surface nets places a cell's vertex at the mean of its edge crossings and the mean of points scattered around a cube's corner sits strictly inside the cube. Both `mesh.rs` and the crate README already carried *aspirational* comments promising dual contouring with nothing behind them; the implementation now exists and those comments are true. Each surface-straddling cell keeps **hermite data** — every edge crossing plus the SDF gradient (surface normal) there — and its vertex is placed by solving the quadratic error function `min Σ (nᵢ·(x-pᵢ))²` for the point best satisfying all those tangent planes at once (new `qef.rs`: `AᵀA` accumulated incrementally, inverted by **pseudo-inverse** via a cyclic-Jacobi symmetric eigen-decomposition). The pseudo-inverse is the load-bearing detail — `AᵀA` is singular exactly in the common cases (a flat patch leaves two directions unconstrained, an edge one), so a plain solve would fling the vertex to infinity; dropping the near-zero eigenvalues and solving relative to the **mass point** keeps those directions at a sane in-cell position, which also makes flat regions degrade gracefully back to surface-nets behavior. Edge crossings are refined by regula falsi against the real field instead of one linear interpolation, so curved and `smooth_union`-blended surfaces get accurate hermite data too. The solved vertex is **clamped into its own cell**: dual contouring's textbook failure is an ill-conditioned solve spiking a vertex outside its cell and self-intersecting the mesh, and the clamp bounds that to "no worse than surface nets" while leaving every well-conditioned feature where it was solved. Topology is untouched — both methods share the same dual quad stage, so triangle counts match exactly and output stays watertight. **Measured on a 20 mm cube at `--res 32`: max vertex deviation 0.0000 mm and volume 8000.00 mm³ (both exact) versus 0.4167 mm and 7932.05 mm³ for surface nets** — and surface nets' error is a fixed ~⅔ of a cell at *every* resolution, so refining the grid never sharpened the feature, it only shrank the rounded region. On a cube rotated off the grid axes the part's own size tells the same story: dual contouring reproduces the analytic bounding box to 4 decimals while surface nets comes up **1.72 mm short**, having shaved the corner away — an undersized print. `bsc cad mesh` now reports a **deviation** pair (max/mean `|SDF|` over the mesh's vertices) so the sharpness is a number a caller can branch on rather than something to eyeball, and `--method dual|surface-nets` selects the polygonizer (dual is the default; the old placement is kept only so the difference stays measurable). New worked example `examples/sharp-block.json` — a 45°-rotated octagonal prism with a diagonal through-slot and two bolt holes, so no face or edge lines up with the sampling grid.
- **`bsc cad` — the geometry kernel joins the unified CLI (#3387, kernel #2621)** — the `bsc-cad` mesh/SDF kernel shipped its foundation (op-tree → SDF → surface nets → binary STL, all in mm) behind its **own** `bsc-cad` binary, which meant no live session could reach it: only `bsc` and `bsc-agent` are bundled with the app (`tauri.conf.json` `externalBin`), so a second sidecar was built by nobody and shipped nowhere. The kernel is now a **subcommand of the one bundled binary** — `bsc cad mesh <spec.json> [-o out.stl] [--res N] [--json|--pretty]` — reachable by absolute path from `$BSC_BIN` with no PATH changes, exactly like `bsc ui` / `bsc graph` / `bsc sound`. The standalone binary is **retired** rather than kept in parallel: every other tool crate (`bsc-shot`, `bsc-navigate`, `bsc-graph`, `bsc-ui`, …) is library-plus-`cli::run` with no `[[bin]]`, and two entry points to one kernel could only drift. The verb surface is the old binary's behavior verbatim (same 96-cell default resolution, same `<spec-stem>.stl` default output, same stats), plus the house `--json`/`--pretty` output contract — the stats now emit structured (`{ spec, out, resolution, bounds_mm, vertices, triangles, watertight, volume_mm3, bytes, empty }`) so an agent iterating on a shape can branch on them. `-h`/`--help` keep working alongside the `bsc cad help` house form. An **empty mesh stays a success** (a valid, empty STL + `empty: true`), since "your spec describes nothing" and "the kernel broke" are different answers to an agent mid-iteration.
- **Headless-browser INTERACTION verification for the preview srcdoc (#3264)** — an opt-in Playwright harness that drives the shipped preview in real Chromium, closing a structural blind spot rather than adding coverage. #3251 (drag stopped panning the Design Studio preview) was the third regression in the #3190 arc to ship green, because jsdom has no text selection, no native drag, no layout and no CSS cascade: a synthetic `mousedown`/`mousemove` pans perfectly there whether or not a browser would, so the test environment could not observe the property under test. The harness runs as a page on a Vite dev server and calls the REAL chain — `bundleComponent` (esbuild-wasm, browser-only) → `collectAppCss` → `buildComponentSrcDoc` → a `sandbox="allow-scripts"` iframe — with the same options `ComponentPreviewFrame` passes, so there is no forked render path. **`collectAppCss`'s live-document dependency is resolved by construction, not by a reimplementation:** the harness page imports `@/styles/tokens.css` exactly as `src/app/main.tsx` does, so the function is exercised unmodified against a real `document.styleSheets`. Seven tests cover both directions of the #3251 trade-off — drag-over-text pans, `user-select` is suppressed on the body but preserved on form fields, an `<img>` drag pans instead of starting a native drag, a plain click still reaches AND focuses a control, a moved drag suppresses its trailing click, a form field still selects text without panning, and the injected `oklch()` token cascade resolves inside the opaque-origin srcdoc. All three ways of breaking #3251 were verified to fail the suite. **Strictly opt-in:** `@playwright/test` is the only new dependency, the browser is a separate one-time `npx playwright install chromium`, `e2e/` is outside the root `tsconfig.json` (so `npm run typecheck` cannot break for a checkout that has not reinstalled — the zero-install nested-worktree workflow of #1669 is untouched) and outside vitest discovery. Run it with `npm run test:e2e`; type-check it with `npm run typecheck:e2e`; `npm run lint` covers it in the normal gate.
- **glTF/GLB export from the geometry kernel (#3389, kernel #2621)** — `bsc cad` emitted **binary STL only**, which is the maker/slicer interchange and a dead end for a viewer: no indexed vertices, no per-vertex normals, no scene graph. `bsc cad mesh` now takes **`--format stl|gltf|glb`** (a flag on the existing verb, not a new one — the shape of the command is unchanged), and the format is **inferred from `--out`'s extension** when the flag is absent, so `-o part.glb` just works. STL remains the default, so every pre-#3389 invocation lands byte-for-byte the file it always did. `gltf` writes a **self-contained** glTF 2.0 text file whose single buffer is an embedded base64 `data:` URI — one file, nothing to resolve, no second fetch, which is the shape an offline WebView preview can consume directly; `glb` writes the standard binary container (JSON chunk + BIN chunk) that external viewers and engines expect. Both carry smooth, **area-weighted per-vertex normals** (the unnormalized face cross-product has magnitude 2×area, so accumulating it weights by area for free) and a neutral PBR material, because a primitive with no material renders as the viewer's default and reads as "broken" rather than "a part". **The mm/Z-up → m/Y-up conversion rides on the scene NODE's matrix rather than being baked into the vertices** — so the POSITION accessor's `min`/`max` stay in the kernel's own millimetre frame and are directly comparable to the `bounds_mm` the CLI reports (a mismatch is then a real bug, not a unit artifact), and the matrix's positive determinant guarantees triangle winding is preserved rather than mirrored. An **empty mesh stays a success**, consistent with the STL path, but must emit a valid *empty scene*: glTF requires `count >= 1`, so zero-count accessors would be spec-invalid and most viewers reject the whole file rather than the empty primitive. The exporter is a new `gltf.rs` consuming the existing `Mesh` — the polygonizer is untouched — and the crate stays dependency-free (base64 is 20 hand-rolled lines) so the WASM build is unaffected. Tests pin the structural invariants a viewer silently dies on: accessor counts against vertex/triangle counts, `byteLength` against what the accessors imply, bufferViews tiling the buffer with no gap or overlap, POSITION bounds against the real f32 data, every index in range, unit-length normals, GLB chunk framing, and the RFC 4648 base64 vectors.
- **The `sound-designer` authoring session (#3369, epic #3071 phase 4)** — the fourth app-owned studio session, alongside the designer (UI kits), librarian (algorithms) and architect (teams). Phases 1-3 of the Sounds pillar had landed the descriptor model, the composition graph, and the `bsc sound` store; this is the session that AUTHORS sound kits. Same posture as its siblings: `none` on every axis (no git, no GitHub, no file writes, no web, no UI kits), launched with `restrictedAllow` so the baseline command tiers are suppressed and its entire auto-runnable surface is `bsc sound` — and, being a restricted role, it can never be flipped to the bypass posture. Its workspace is `~/.base-studio-code/sound-studio/`, whose `CLAUDE.md` is a packaged, config-dir-overridable seed carrying the four-layer model (primitives -> voices -> cues -> kits), the synthesis-first rule (a sound is a descriptor, never a binary asset), and the discover-before-write / verify-after-write discipline. It joins the Studio Network graph as a node stewarding a new Sound library resource, so it opens as an in-graph morph like every other studio, and it is excluded from crash recovery like its siblings. **Naming note:** `sound-designer` shares a word with `designer` but is a wholly distinct role -- a test pins that their command surfaces and capabilities never conflate.

- **Open several node sessions at once in Glance, snapped to a grid (#3361)** — clicking a live agent used to REPLACE whatever was already open: `chatNode` held one id and the canvas rendered at most one keyed morph. Several nodes can now be open simultaneously. Morphs stay **in the graph** — a node still grows in place into its live session, which is the whole point of the morph (#2534) — but each grows into a discrete **grid slot** rather than free-floating at its own coords, so two open morphs can never overlap. **The first opened node defines the grid:** its morph lands exactly where a lone morph always has (the cell centred on its own node), and that box becomes cell (0,0); every later morph aligns to the lattice built off it. The lattice is **signed and directional** (#3367) — a node to the LEFT of the anchor opens to the left of it, one above opens above, diagonals land on diagonal cells — so the arrangement reads as a spatial projection of the graph rather than an arbitrary queue. Placement scores every free cell by how well its direction matches the node's own offset from the anchor node, docked by distance, so a fourth left-hand node spills further left instead of dropping into a nearer cell on no particular side. The anchor is held as a node ID rather than frozen coordinates, so the grid tracks the graph when the layout recomputes, and it is retained even if the anchor's own morph closes — the remaining morphs never shift under the user. Slots are stable while open: closing one frees its slot for the next open without reflowing its siblings, because a terminal you are reading must not jump. Resizing any morph now drives the grid's **shared cell size**, so they all resize together and stay a grid. The graph parts around the **union** of the open morphs — one region, so the existing four-curtain model (#2671) is unchanged whether one morph is open or six — and each morph releases its box the instant it starts collapsing, so the neighbours part back in step with the shrink. Escape and a click on empty canvas still dismiss (both non-destructive — every PTY survives); a click inside any card, **and a click on any graph node**, dismisses nothing (#3365 — a node press is an open/select gesture, and treating it as a dismiss meant opening a second node tore down the first, leaving only one morph visible and silently defeating the grid).

### Changed
- **The base motions belong to a `base` kit, not to `react-ui` (#3451, epic #3260)** — `lift` / `fade-in` / `pulse` are a base motion vocabulary the whole platform leans on, but they were authored INSIDE the `react-ui` demo kit's primitives (Button / Card / StatusDot) and lifted into `REACT_UI_KIT.animations` at generation. One demo kit therefore OWNED shared motion: a project adopting a different kit lost it, and the app's own UI could not reference it as shared graph data. The defs now live in ONE place — a new `base` kit (`shared/ui/kit/baseAnimations.ts` + `features/designs/lib/baseKit.ts`) — and every consumer REFERENCES them by name, so editing `lift` once updates every consuming kit with no regeneration. **That shared resolution IS the propagation mechanic applied to motion**, and the first concrete step toward the app's own UI being graph data. The manifest's `PrimitiveSpec.animations` becomes name-REFS (`string[]`) instead of full defs, `collectKitAnimations` is deleted, and `REACT_UI_KIT.animations` is deliberately empty — so there is exactly one definition of each motion, never a duplicate. **The load-bearing decision is the namespace:** a base-resolved def KEEPS `kit: "base"` rather than being restamped to the consumer, because that field names BOTH the compiled `@keyframes bsc-base-<name>` and the `.base-anim-<name>` hook the preview stamps — so every consumer shares ONE keyframes block (restamping would duplicate it per kit and defeat propagation, and a half-applied restamp would leave the class not matching the rule, i.e. the animation silently playing nothing). A kit's OWN definition still wins over the base one of the same name, so a kit can override a base motion. The `base` kit seeds **unconditionally** alongside the viz kits rather than behind `DEFAULT_KIT_SEEDED` (off since #3029): react-ui's primitives now reference its animations, so a gated `base` would leave them unresolvable — a regression with no error, just motionless components. It gets its OWN rail style (`motion`) rather than joining react-ui's `studio`, since a `style` denotes a structurally different COMPONENT SET and a shared motion library is not one. Tests pin the cross-kit resolution end-to-end (own-kit precedence, the base fallback, the preserved `kit: "base"` stamp, a dropped dangling ref, inline defs unaffected, and the base shelf reachable for a try-on from another kit), that no primitive references a base animation that doesn't exist, and that `base` reaches a store that lacks it regardless of the flag.
- **Backend `org` → `teams` rename (#2700, backend half of the frontend/store rename)** — the Rust crate `bsc-org` becomes `bsc-teams` (lib `bsc_org` → `bsc_teams`), and the session-facing CLI verb `bsc org` becomes **`bsc teams`** as the primary, with `bsc org` kept as a **deprecated alias** that still routes to the same store handler and prints a one-line stderr note (stdout stays clean JSON for pipes) — mirroring the `bsc component` → `bsc ui` deprecation (#2469), so live agent sessions calling `bsc org` keep working. The agent CLI inventory (`bsc_util::SIDECARS`) + `bsc`'s top-level help now advertise `teams`. The packaged seed dir `src-tauri/data/org/` moves to `src-tauri/data/teams/` and its frontend loaders (`@data/org/*` imports + the config-dir overlay paths in `team.ts`/`TeamsPanel.tsx`) follow. The frontend teams bridge (`orgBridge.ts`) now calls `bsc teams`. **Data-safety KEEPs:** the on-disk user store directory stays `~/.base-studio-code/orgs/` (env `BSC_ORG_DIR`, `dir_segment`/`noun` unchanged) so no existing saved data is orphaned, and the mobile tunnel wire contract (`bsc-tunnel` `store_domains::ORG` + the `orgs`/`OrgPayload` field) is untouched pending a coordinated mobile-studio-code change.

### Fixed
- **The librarian spec-drift gate was RED and protecting nothing (#3477)** — `packaged_librarian_spec_names_only_verbs_the_cli_has` exists to catch a spec that sends the librarian at verbs its CLI rejects, and it had been failing, so it caught nothing. TWO real causes: (1) the spec's `bsc request new "…"` EXAMPLE TITLE said `bsc graph list`, a verb that does not exist, while its own `--cmd` correctly used `bsc graph impl list` — the title and the command disagreed; (2) the flag assertion scanned **every** `--token` in the whole document and asserted each was a `bsc graph` flag, but the spec also teaches OTHER CLIs (`bsc request new … --cmd … --surface`, the loop verbs), so another CLI's flags were attributed to `bsc graph`. The title is corrected and the flag scan is now scoped to lines whose FIRST `bsc <cli>` invocation is `graph`. The gate is green for the first time, which matters because it is the only thing standing between a spec edit and a session being taught a command that does not exist.
- **Both harvests read outside the session's FS confinement — now bounded by `$BSC_REPO_ROOT` (#3475/#158)** — `bsc-confine` reads `file_path`/`notebook_path` out of the PreToolUse payload, so it gates **Claude's file tools** and is structurally blind to what a spawned binary reads. `bsc ui harvest` (#3471) and `bsc graph harvest` (#2745) both take a directory and hand back file CONTENTS, so a deliberately-confined studio session could read any path on disk through them: the **designer** and **librarian** are limited to their own studio workspace and are BLOCKED from `Read`-ing a repo file, yet `bsc ui harvest <any-path>` returned every component's full `srcText` and `bsc graph harvest <any-path>` every function's full `code`. **The grant was never the gap** — `restrictedRoleCommands` already gives those roles the bare `"bsc ui"` / `"bsc graph"` prefixes, which `bash_rule` expands to `Bash(bsc ui *)` / `Bash(bsc graph *)`, and those already prefix-match `… harvest`. What was missing was a boundary, so widening permissions would have been exactly the wrong fix. Both verbs (and `bsc graph curate`) now call a new `require_within_repo_root` — deliberately placed beside `require_write_scope` in `bsc-cli-util`, because it is the same kind of gate and the CLI layer is where a session-imposed limit belongs. An **unset or empty** root means an unconfined session (a plain console, a direct CLI run) and is allowed unchanged, so this is fully back-compatible; when the root IS set, both sides go through `canonicalize` before comparing, so `..` segments and symlinks cannot walk out (a naive string-prefix check would let `<root>/sub/../..` sail through, which is pinned by a test). A root that cannot itself be resolved **fails closed** — a misconfigured confinement must not silently degrade into no confinement at all. The comparison normalizes git-bash drive paths first (`/c/Users/…` → `C:/Users/…`), because `pty_create` writes `$BSC_REPO_ROOT` in BASH form and a native-vs-bash comparison would never match. **The two harvest extractors stay separate** so the component and algorithm pillars can be improved and optimized independently — only the boundary primitive is shared. Its test seam is **thread-local** (`with_repo_root`, joining `with_scopes`/`with_scratch`), never `set_var`: `cargo test` runs a crate's tests as parallel threads of one process, and a process-env seam would race every sibling exactly as #3382 documented — pinned by a test asserting a sibling thread stays unconfined while this one is bounded.
- **The BYO/`bsc-agent` Anthropic path set zero prompt-cache breakpoints — full input price re-paid every turn (#3458, epic #3260, step B of the metric plan)** — the model-agnostic path (`crates/llm`, the runtime behind `bsc-agent` and `llm_complete` when driven by an Anthropic key) built the `/v1/messages` body with **no `cache_control` anywhere**: `build_request_body` / `turn_request_body` sent a bare `system` string and plain `tools`, so the large, byte-identical prefix every turn shares — the role/persona system prompt plus the tool definitions — was billed at full input price on every single turn of a session. Anthropic renders the request prefix as `tools → system → messages`, so the fix is **one** breakpoint, not a scatter of them: `cached_system` converts a non-empty `system` into a one-element text-block array carrying `cache_control: {type: "ephemeral"}`, and because that block renders *after* the tools, the single breakpoint caches the whole tools+system prefix at once. The response side needed nothing — `normalize_usage` already surfaced `cache_creation_input_tokens` / `cache_read_input_tokens`, and the non-turn `complete` path returns the raw response whose usage is already the cache-aware shape — so the split now flows straight into `cost.rs` and the `bsc metrics` cache-hit dial (#3449). **Three deliberate non-regressions:** an EMPTY system stays the pre-#3458 bare string (nothing to cache, so no odd empty breakpoint); a prompt below the model's minimum cacheable prefix (2048 tokens on the `claude-sonnet-4-6` default, 4096 on Opus) silently doesn't cache, which is a no-op rather than an error; and **no beta header** is added, because prompt caching is GA.
